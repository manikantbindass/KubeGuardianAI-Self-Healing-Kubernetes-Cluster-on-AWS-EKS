## Phase 00: foundation

environment examples, architecture Mermaid, roadmap, editor/Git settings and
repository validator. `npm run lint:docs`, `npm run diagrams`,

Generated CRDs appear in both operator and chart paths intentionally; CI checks
generation drift. The named service directories contain honest ownership notes
where logic is integrated into the API/operator; they are not independent running
services merely because directories exist.

## Phase 01: full-stack foundation

Reviewed FastAPI routers, settings, schemas, SQLAlchemy models/session lifecycle,
migrations, queue worker, same-origin Next.js proxy, TypeScript client, Compose
and Dockerfiles. Baseline CI `api` on Windows/Linux, `dashboard`, `migrations` and
`containers` succeeds. Fresh Python and frontend checks are recorded below.

Health is process liveness; readiness requires PostgreSQL schema revision
`0005_queue_index` plus Redis. Migrations must run before API/worker startup.
SQL row locking and PostgreSQL admission advisory locks provide queue durability
and multi-replica bounds; SQLite unit tests do not prove these semantics.
The legacy public greeting interface remains suitable only behind local/network
boundaries. Operations authentication does not wrap all legacy routes.

## Phase 02: Kubernetes

Reviewed application, observability and recovery charts, namespace/Service/RBAC,
NetworkPolicies, resources, probes, API HPA, PDB, optional ingress and bootstrap
scripts. Baseline `kind` and real operations `cluster` CI succeed. Local/dev/prod
rendering and strict schemas are checked by the delivery validator.

Local kind policy enforcement depends on the configured CNI; manifest presence

explicit and its mutation allowlist is separate from dashboard access.
Docker Desktop launch was attempted; Linux engine remains unavailable locally.

## Phase 06: deterministic recovery

Reviewed controller reconciliation, native fault classification, typed CRDs,
policy selection, action naming, policy-version-bound approvals, audit state
transitions, mutation revalidation, rollout verification and exact-template undo.
Classifications include crash loops, OOM, readiness, restarts, rollout deadline,
replica shortage and pressure; latency/pressure alone escalate rather than allow
unsafe mutation. External recommendations do not select controller actions.

The controller independently checks namespace/workload allowlists, opt-in,
policy/target UID and generation, expiry, healthy replicas, maintenance, cooldown,
action budgets and approval signatures. It defaults to dry-run. Leader election
and single reconciliation concurrency prevent conflicting active work; durable
action identity prevents duplicate execution. No arbitrary pod deletion path is
available to the recovery controller. RBAC permission tests and isolated-recovery
CI passed at the baseline. Current Go security updates require fresh tests.

Escalation is a durable action/audit state; delivery to an external notification
provider is not implemented. Recovery evidence comprises a small isolated set of
action records, not repeated statistical recovery trials. No production claim.
