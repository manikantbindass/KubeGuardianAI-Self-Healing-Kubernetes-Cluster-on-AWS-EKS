# Model card: Phase 05 advisory detectors

## Intended use

Offline reproducibility and trusted local Kubernetes anomaly-scoring experiments. Rules are the default. Robust statistics and Isolation Forest are comparison models, not approved autonomous recovery systems. None executes remediation or estimates calibrated incident probabilities. Real deployments require independent labeled workload evaluation, access controls and operator approval.

## Data and lineage

The reference dataset is generated by `synthetic-v1`, seed 42, 900 minutes, 1800 observations. It includes CPU saturation, memory/restart faults, HTTP errors/latency and scheduling/node-pressure patterns. All observations are explicitly synthetic, with incident IDs and fault start times. Small missing-CPU samples exercise null handling. This generator is intentionally simple, not a workload diversity benchmark; repeated pattern families and easy rule thresholds limit external validity.

The [saved metadata](synthetic-v1-metadata.json) records exact dataset/code/model hashes, parameters, package/Python versions, feature order, split boundaries and incident lineage. Raw datasets/forest artifacts are generated locally, not committed. The repository license covers the generator; operators must separately authorize real telemetry collection, redaction, retention and labels. No user/production telemetry was used in reference training.

## Models and preprocessing

Fixed severity rules form the baseline. Robust statistics use training medians, scaled MAD with documented floors and maximum absolute deviation. Isolation Forest uses 64 trees, maximum 256 samples, seed 42 and one training thread. Input features are causal 60-second aggregates with past-only trends; dimensions/order are versioned. Known positive training windows are excluded, normalization is training-only, threshold tuning is validation-only. The final test set remains held out with temporal/incident purging.

JSON forest inference is tested against scikit-learn. Checksums, topology, finite values and dimensions are validated without executable deserialization. Checksums are not signatures. Artifacts require provenance and operator access controls.

## Empirical results and interpretation

Use the [evaluation JSON](../../docs/reports/phase-05/evaluation.json), [predictions](../../docs/reports/phase-05/predictions.csv) and [validation record](../../docs/reports/phase-05-validation.md). They report measured precision/recall/F1/FPR, confusion matrices, detection delays/misses, latency and plots. The reference rules outperform both ML models on this fixture; no ML promotion is justified. Thresholds are uncalibrated scores, never probabilities or confidence percentages. Validation FPR constraints do not guarantee test/live false-positive rates.

Feature evidence highlights robust deviations, not root cause or faithful Isolation Forest attribution. Detection delay excludes missed incidents, which are separately listed. Short synthetic timing and warm-process latency exclude collection, Prometheus smoothing, queueing and network latency; the HTTP load report measures a separate end-to-end service path.

## Limitations and promotion gate

- Only one synthetic resource and a small number of held-out incident episodes; no real-world accuracy claim.
- Namespace aggregates hide individual workloads; changing resource requests/limits changes feature meaning. Traffic seasonality, deployment churn and unseen failure modes can create false positives/misses.
- Missing coverage activates rules with an explicit quality flag, not inferred health. Unlabeled baseline contamination and bad incident labels can invalidate training.
- Robust shift/clipping flags are advisory; they do not prove concept drift. Counters reset on restart and no automatic retraining occurs.
- Incident delivery is opt-in, real-only, at-least-once with retry/deduplication; it is not a durable job queue or full incident lifecycle manager.
- No production OIDC/tenant isolation, signed registry, independent calibration, security review or automated promotion exists.

Before promotion: collect authorized diverse real telemetry, review labels, keep incident families/time separated, evaluate multiple windows/workloads/seeds, compare operating points with rules, measure sustained overhead/delay under faults/outages and approve a rollback artifact. Require clear baseline improvement or retain rules. LSTMs/autoencoders remain deferred until data volume and evaluation justify them.
